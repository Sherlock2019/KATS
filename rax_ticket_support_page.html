RAX Core Legacy

The ticket view in use today
  • Records what happened to the ticket — queue moves, assignments, status changes, work logged
  • Free-text everything — account, category and notes are typed, so nothing groups or counts
  • Comment thread as the only narrative, colour-coded by author
  • No problem structure — no deviation statement, no IS / IS NOT, no distinctions, no root-cause category
  • Knowledge stays in people's heads — a solved ticket teaches the next one nothing

KATS

KT AI Enhanced Ticket Support System
  • Records the problem, not just the ticket — Kepner-Tregoe intake: WHAT, WHERE, WHEN, TREND, HOW MANY
  • Automatic triage — on open it answers: is this already open elsewhere, seen before, working as designed, is there a known fix
  • Controlled facets — customer, component and root-cause category are coded, so they group, count and rank
  • Problem records that outlive the ticket, with recurrence counts and blast radius
  • Every solved case feeds the Knowledge Base — the next engineer starts where the last one finished
